# 二期子项目 A：时间/校区修改审批流 设计文档

日期：2026-10-26
状态：待用户确认
依据：一期设计文档 `docs/superpowers/specs/2026-10-26-排课工具-design.md`

## 1. 背景与目标

一期中老师的时间/校区修改直接生效（`approvalStatus` 字段预留但未启用）。
二期引入审批流：老师提交修改 → 管理员审批 → 通过后生效。

目标：
- 老师批量修改时间和校区，打包成一个审批单提交
- 管理员在审批通过时校验新时段与已排课程的冲突，有冲突则禁止通过
- 审批期间旧版本数据继续生效（排课筛选、课表查询不受影响）

## 2. 核心决策（已与用户确认）

| 决策项 | 结论 |
|---|---|
| 审批期间数据版本 | 旧版本继续生效，审批通过后才替换 |
| 冲突处理 | 硬阻断：审批通过时若新时段不覆盖某已排课，禁止通过 |
| 提交粒度 | 批量提交：一次调整多条时段，整体打包一个审批单 |
| 审批单内容 | 完整新快照（新时段列表 + 新校区列表） |
| 时间+校区 | 合并到同一个审批单 |
| 撤回 | 老师可撤回待审批申请 |
| 驳回原因 | 选填 |
| 并发 | 同一老师同时只允许一个 pending 审批单 |

## 3. 数据模型

### 3.1 approvals 表扩展

现有字段：`id, type, targetId, status, payload, createdAt, updatedAt`

新增字段：
| 字段 | 类型 | 说明 |
|---|---|---|
| `submitterId` | text | 提交人 userId |
| `approverId` | text | 审批人 userId（审批后写入） |
| `rejectReason` | text | 驳回原因（选填） |

字段语义：
- `type` = `'availability_change'`
- `targetId` = teacher.userId
- `status`：`'pending'` | `'approved'` | `'rejected'` | `'withdrawn'`
- `payload`：
  ```json
  {
    "slots": [{ "type": "weekly"|"date", "weekday": 0-6|null, "date": "YYYY-MM-DD"|null, "startTime": "HH:mm", "endTime": "HH:mm" }],
    "campuses": ["campusId1", "campusId2"]
  }
  ```

### 3.2 其他表

- `availabilities`：不变，审批通过后直接删除旧记录+插入新记录（`approvalStatus` 保持 `'approved'`）
- `teachers`：不变，审批通过后更新 `campuses` 字段

## 4. 后端接口

### 4.1 availability 云函数（新增 handlers）

#### submitChange（老师提交审批）
- 入参：`{ slots, campuses }`
- 权限：teacher
- 逻辑：
  1. 校验该老师无 pending 审批单（有则 400）
  2. 校验时段合法性：结束>开始、不跨天、临时日期≥今天、星期 0-6
  3. 校验同时域不重叠（`slotOverlapsExisting`）
  4. 校验校区都存在
  5. 写入 approvals 表（status=pending, type=availability_change, targetId=teacher.userId, submitterId, payload）
- **不修改** availabilities / teachers 表

#### getMyPendingChange
- 入参：无
- 权限：teacher
- 返回：当前 pending 审批单或 null

#### listMyApprovals
- 入参：无
- 权限：teacher
- 返回：该老师的审批列表（按 createdAt 倒序，含状态、快照、驳回原因）

#### withdrawApproval
- 入参：`{ approvalId }`
- 权限：teacher（只能撤回自己的）
- 逻辑：校验状态=pending → 置为 withdrawn

### 4.2 approval 云函数（新建）

#### list
- 入参：`{ status? }`
- 权限：admin
- 返回：审批列表（含老师姓名，按 createdAt 倒序）

#### get
- 入参：`{ approvalId }`
- 权限：admin
- 返回：审批单详情 + 该老师当前生效的时段列表和校区列表（供前端对比）

#### approve
- 入参：`{ approvalId }`
- 权限：admin
- 逻辑（**先校验旧状态=pending**，再操作）：
  1. 读取审批单，校验 status=pending
  2. 解析 payload 得到新时段列表
  3. **冲突检查**：查询该老师所有 BLOCKING_STATUS（pending/confirmed）的 sessions，对每个 session 构造 occ，用 `isCovered(newSlots, occ)` 校验；有不覆盖的 → 收集冲突
  4. 有冲突 → 返回 `{ code:400, message:'新时段与已排课程冲突', conflicts:[{date, startTime, endTime, studentName, courseId}] }`
  5. 无冲突 → 应用快照：
     - 删除该老师所有 availabilities
     - 批量插入新时段（approvalStatus='approved'）
     - 更新 teachers.campuses
  6. 更新 approval：status=approved, approverId

#### reject
- 入参：`{ approvalId, rejectReason? }`
- 权限：admin
- 逻辑：校验 status=pending → 置为 rejected，写入 rejectReason

### 4.3 冲突检查算法

```
新时段 slots（完整快照）
该老师所有 blocking sessions（status in ['pending','confirmed']）

for each session:
  occ = { date, weekday: weekdayOf(date), startMin: toMinutes(startTime), endMin: toMinutes(endTime) }
  if !isCovered(slots, occ):
    conflicts.push({ session, studentName })

if conflicts.length > 0:
  return 400 + conflicts
else:
  apply snapshot
```

## 5. 前端改动

### 5.1 老师端 Availability.vue（我的时间）

- 改为编辑模式：本地维护时段列表（可增删），点「提交审批」一次性提交
- 若有 pending 单：显示「审批中」横幅，锁定编辑，提供「撤回」按钮
- 底部显示审批历史（状态、驳回原因）

### 5.2 老师端 Campuses.vue（我的校区）

- 校区选择整合到 Availability 页的编辑流程中，与时段修改一起提交
- Campuses.vue 改为只读展示当前已生效的校区（编辑入口在 Availability 页）

### 5.3 管理端 Teachers.vue

- 新增「时间审批」Tab
- 列表：老师姓名、提交时间、状态筛选（pending/approved/rejected/withdrawn）
- 详情：左右对比旧时段 vs 新时段（新增绿色、删除红色高亮），校区变更对比；若有冲突显示冲突课程
- 操作：通过 / 驳回（原因选填）

## 6. 一期兼容性

- 一期 `availability.addSlot/removeSlot/setCampuses` 直接生效 → **保留为管理员专用**（管理员修改老师时间无需审批）
- 老师端统一走 `submitChange`，不再调用 addSlot/removeSlot/setCampuses
- `listMy` 逻辑不变（仍读 availabilities + teachers 表，即旧版本生效中）
- `filterTeachers`（排课筛选）不变（仍读 availabilities 表）

## 7. 状态机

```
pending ──approve──▶ approved（快照应用到 availabilities/teachers）
   │
   ├─reject──▶ rejected（rejectReason）
   │
   └─withdraw─▶ withdrawn
```
同一老师同时只允许一个 pending。

## 8. 错误处理

- 老师提交时已有 pending 单 → 400「已有待审批申请，请等待审批或撤回」
- 管理员通过时有冲突 → 400 + 冲突课程列表
- 管理员驳回/通过非 pending 单 → 400「该申请已处理」
- 老师撤回非自己的单 → 403

## 9. 测试策略

- 单元测试：冲突检查算法（新时段覆盖/不覆盖已排课的各种边界）
- e2e：老师提交 → 管理员通过（无冲突）→ 数据更新；老师提交 → 管理员通过（有冲突）→ 拒绝；老师撤回；管理员驳回
