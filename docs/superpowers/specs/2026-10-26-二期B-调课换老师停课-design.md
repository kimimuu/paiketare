# 二期 B：调课 / 换老师 / 停课 设计文档

日期：2026-10-26
状态：已获用户批准，待实现

## 1. 背景

一期 + 二期 A 已具备"发起排课 → 老师确认 → 老师时间审批"完整链路。二期 B 补齐管理员对已排课程的运营调整能力：单次调课、系列换老师、提前停课。三项操作均为管理员手动执行，直接生效，不走审批流。

## 2. 功能语义

| 功能 | 对象 | 变更范围 | 校验 |
|---|---|---|---|
| **调课** rescheduleSession | 单次 session | 改 date + startTime + endTime + campusId | 新校区 ∈ 老师可带校区 + 新时段落在老师可用时段内 + 新时段不与同老师其他 BLOCKING session 冲突 |
| **换老师** changeTeacher | course + future sessions | course.teacherId + 未上课的 pending/confirmed sessions.teacherId 一起改；历史已完成/已取消 session 不动 | 新老师能在原校区上课 + 对每个 future session：时段在新老师可用时段内 + 不与新老师其他 BLOCKING session 冲突 |
| **停课** endCourse | course + 所有 sessions | course.status→cancelled, endReason='cancelled_by_admin'，所有 sessions WHERE status∈BLOCKING → status=cancelled | 无（管理员强制生效） |

## 3. 数据库改动

**courses 表** 新增字段（默认空字符串表示未结束）：
```sql
"endReason" text NOT NULL DEFAULT ''
```
取值：`''`（未结束）、`'finish'`（正常上完）、`'cancelled_by_admin'`（管理员停课）、`'other'`

**sessions 表** 结构不变，状态值沿用 `pending/confirmed/cancelled`。

**迁移脚本**：`scripts/migrate-course-ops.js`
```sql
ALTER TABLE courses ADD COLUMN IF NOT EXISTS "endReason" text NOT NULL DEFAULT '';
CREATE INDEX IF NOT EXISTS courses_end_reason_idx ON courses("endReason");
```

`scripts/schema.sql` 同步更新 courses 定义。

## 4. 后端实现

全部 handler 追加到现有 `cloudfunctions/course/index.js`，不新增云函数。三个 handler 均用 `requireAuth(event, 'admin')` 保护。

### 4.1 rescheduleSession

```js
// 入参
{ sessionId, newDate, newStartTime, newEndTime?, newCampusId? }

// 校验流程
// 1. session 存在 && status ∈ BLOCKING_STATUS
// 2. 从原 course.duration 推导 newEndTime（若未传），或直接用传入值
// 3. 取 teacher availabilities + teachers.campuses + 除当前 session 外的所有 BLOCKING sessions
// 4. 构造单 occurrence：{date, weekday, startMin, endMin}
// 5. campuses.includes(newCampusId)? 新校区合法
// 6. isCovered(availSlots, occ)? 时段覆盖
// 7. 不与其他 BLOCKING session 冲突
// 8. 全部通过 → update sessions set date/startTime/endTime/campusId
```

**冲突时返回**（通过 resp.js wrap 提取 Error 附加字段）：
```json
{ "code": 400, "message": "调课失败：2026-10-27 19:00-20:00 与张老师另一节 2026-10-27 18:30-19:30 冲突",
  "conflicts": [{ sessionId, courseId, date, startTime, endTime, studentName }] }
```

### 4.2 changeTeacher

```js
// 入参
{ courseId, newTeacherId }

// 校验流程
// 1. course 存在 && status !== cancelled && newTeacherId !== course.teacherId
// 2. today = todayStr(); 取 course 的所有 BLOCKING sessions
// 3. futureSessions = sessions.filter(s => s.date >= today)
// 4. 取新老师 availabilities + teachers.campuses + 新老师所有 BLOCKING sessions（排除当前 course 的 sessions）
// 5. 对每个 future session:
//    a. newCampuses.includes(session.campusId)? 新老师能在该校区上课
//    b. 构造 occ = {date, weekdayOf(date), startMin, endMin}
//    c. isCovered(availSlots, occ)?
//    d. 不与新老师其他 BLOCKING session 冲突
// 6. 全部通过 → update courses.teacherId; 批量 update future sessions.teacherId
```

**校验不通过**：返回第一个不通过的 session 详情。

### 4.3 endCourse

```js
// 入参
{ courseId, reason? }   // reason 可选，默认 'cancelled_by_admin'

// 流程
// 1. course 存在 && status ∈ [pending, confirmed]
// 2. 批量 update sessions WHERE courseId AND status IN BLOCKING_STATUS → status = 'cancelled'
// 3. updateById courses → status = 'cancelled', endReason = reason || 'cancelled_by_admin'
// 4. 返回 { cancelledSessions: N }
```

无校验，管理员强制生效。

### 4.4 冲突校验复用

三个 handler 共用 course/index.js 内部抽取的辅助函数：
```js
// 抽取：校验某老师对一组 occurrences 是否都能在指定校区上课
async function assertTeacherCanOccupy(teacherId, occurrences, campusId, excludeCourseIds = [])
// 内部：取 availabilities + campuses + 排除的 BLOCKING sessions → 逐 occurrence 调 isCovered + 冲突检查
```

同时让 `rescheduleSession` 用简化版（单个 occurrence + 已有 session 排除），`changeTeacher` 用批量版。

## 5. 前端实现

在**管理端课表页** `frontend/src/views/admin/Schedule.vue` 增加操作面板。

> 注：当前 Schedule.vue 现状待读 —— 一期可能只有列表展示无行级操作。确认后在实现阶段再评估是否拆成"点击行 → 右侧抽屉/弹窗 → 三个操作按钮"。

**交互模式**：点击某条 session 行 → 弹出操作弹窗（含该 session 完整信息）→ 三个按钮：调课 / 换老师 / 停课。

**调课弹窗**：
- 日期：原生 date picker（≥ 今天）
- 开始时间 / 结束时间：time picker（duration 自动保留原值，用户改开始时间则结束时间自动推）
- 校区：下拉列表（从 baseData.listCampuses 取）
- 提交：调 course.rescheduleSession → 失败展示冲突 → 成功关闭弹窗 + 刷新课表

**换老师弹窗**：
- 老师下拉：调 schedule.filterTeachers({campusId, type:'regular', weekday:'?', startTime, duration, totalSessions:1}) — 但需要支持"无星期几约束（因为 session 是按日期的）"。实际用简化版：取所有 active 老师，逐个检查能否带这个 session。
- 简化：直接调 `baseData.listTeachers` 拉全部老师 → 前端逐个调可用性？太重。
- **最终方案**：在 course 云函数加一个轻量 handler `findCandidatesForReschedule({ campusId, date, startTime, duration, excludeTeacherId })`，后端用现有 availabilities + sessions 快速筛选，返回可用老师列表。

**停课弹窗**：二次确认框（"将取消所有未上的课，此操作不可撤销。确定？"）→ 确认后调 course.endCourse → 刷新课表 + toast。

## 6. 错误处理

| 场景 | 处理 |
|---|---|
| 调课到老师不可用时段 | 400 + message 说明 + 可选 conflicts 详情 |
| 换老师但新老师某一天冲突 | 400 + 第一个冲突的 session 详情 |
| 对已 cancelled 的 course 操作 | 400 "课程已结束" |
| 对已完成的 session 调课 | 400 "已完成的课不能调整" |
| sessionId/courseId 不存在 | 400 "参数错误" |
| 非 admin 调用 | 403 |
