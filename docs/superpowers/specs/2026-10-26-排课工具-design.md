# 排课工具设计文档

日期：2026-10-26
状态：已获用户口头批准，待书面确认

## 1. 背景与目标

英语培训机构需要实时排课工具。现状痛点：老师可排课时间分散、每次排课需逐个询问；多校区（16个）；课程分体验课（30分钟、日期随机）与正式课（2小时、每周固定重复）。

目标：老师自主录入每周可上课时间段与可带课校区；管理员输入上课需求后，系统自动筛选出符合条件的老师列表，管理员选定后老师确认生效。

规模：300+ 老师、16 校区、约 300 节课/天。

## 2. 角色与账号

| 角色 | 人数 | 设备 | 权限 |
|---|---|---|---|
| 管理员 | 2 | 电脑+手机 | 全部功能 |
| 老师 | 300+ | 手机为主 | 录入时间/校区、确认排课、查看课表 |

账号体系：
- 管理员账号由系统初始创建
- 老师账号两种方式开通：① 管理员批量导入（姓名+手机号，生成初始密码）② 老师自主注册（姓名+手机号+自设密码）→ 管理员审批后生效
- 登录方式：手机号 + 密码；首次登录强制修改密码

## 3. 核心业务规则

### 3.1 课程类型
- **体验课**：单次 30 分钟，任意日期任意时段，必须指定校区；同一学生可有多节体验课，每节单独发起排课
- **正式课**：单次 2 小时，每周固定星期几+固定时间点重复，创建时设置**总次数**，上完自动结束；中途允许调单次课时间或整体换老师（仅管理员手动操作）

### 3.2 老师可排时间
- 两种录入方式并存：① 每周规律（星期几 + 时间段，如周一三五 18:00-21:00）② 临时时间（具体日期 + 时间段）
- 修改规则：老师提交修改 → 管理员审批 → 通过后生效；审批时若与已排课程冲突，系统明确提示

### 3.3 排课筛选规则
老师出现在候选列表需**同时满足**：
1. 可带课校区包含目标校区
2. 可排时间（规律+临时）完整覆盖需求时段
3. 该时段无已确认或待确认的课程（冲突**禁止**，不满足即不出现在列表）
4. 正式课系列：校验总次数内**每一次**课的时间

### 3.4 状态机
- 排课：管理员发起 → 老师待确认 → 确认（生效）/ 拒绝（退回，管理员重选老师）
- 时间修改：老师提交 → 待审批 → 通过（生效）/ 驳回

### 3.5 明确不做（YAGNI）
- 不计算校区间通勤距离与通勤间隔（老师自主申报可带校区）
- 不限制同老师同日跨校区
- 校区无教室数量上限
- 候选老师列表不排序、无优先级
- 无老师课时上限
- 不做微信/短信通知；老师通过待办列表主动查看待确认排课（站内消息推送属二期）

## 4. 功能模块

### 4.1 老师端（手机网页）
1. 登录/注册/修改密码
2. 我的时间：规律时间 + 临时时间的增删改（修改走审批）
3. 我的校区：16 校区多选（修改走审批）
4. 待办：待确认排课（确认/拒绝）、审批进度查看
5. 我的课表：按周查看已确认课程
6. 站内消息

### 4.2 管理端（电脑/手机响应式）
1. 仪表盘：今日课程、待审批、待确认排课数量
2. 排课页（核心）：选课程类型 → 选学生、校区、时间（正式课选星期几+时间点+总次数）→ 展示候选老师列表 → 选定发出
3. 课表页：按天/周视图，按校区或老师筛选
4. 老师管理：批量导入、注册审批、时间修改审批、手动调课/换老师/停课
5. 学生管理：姓名、校区、电话
6. 校区管理：16 校区维护
7. 数据导出：课表、老师时间等导出 Excel

### 4.3 学生数据
字段：姓名、校区、电话。排课时必须关联学生。

## 5. 数据模型（CloudBase 云数据库集合）

| 集合 | 关键字段 |
|---|---|
| `users` | 手机号、密码哈希、角色（admin/teacher）、状态 |
| `teachers` | userId、可带校区列表、注册审批状态 |
| `campuses` | 名称、地址（可选） |
| `availabilities` | teacherId、类型（weekly/date）、星期或日期、开始/结束时间、审批状态 |
| `students` | 姓名、校区、电话 |
| `courses` | 类型（trial/regular）、studentId、teacherId、campusId、状态 |
| `sessions` | courseId、日期、开始/结束时间、状态（待确认/已确认/已完成/已取消） |
| `approvals` | 类型（时间修改/校区修改/注册）、提交人、内容快照、状态、审批人 |
| `messages` | 接收人、类型、内容、已读状态 |

## 6. 技术架构（方案B：腾讯云开发 CloudBase）

```
老师手机 / 管理员电脑（浏览器，静态网站托管）
        ↓
响应式网页：Vue3 + Vant（移动端组件库）
        ↓ HTTPS
云函数（Node.js）：登录鉴权、排课筛选、审批流、Excel 导出
        ↓
云数据库（文档型）+ 云存储（导出文件）
```

- 登录鉴权：CloudBase 自定义登录（手机号+密码）
- Excel 导出：云函数用 ExcelJS 生成文件存云存储，返回临时下载链接
- 成本预估：按量付费约 30-80 元/月

### 排课筛选实现
云函数接收（类型、校区、日期/星期、开始时间、时长、总次数）→ 查询候选老师（校区匹配）→ 过滤时间覆盖 → 过滤冲突（查 sessions 交集）→ 返回老师列表。

## 7. 错误处理

- 并发排同一老师同一时段：以老师确认为准，确认时二次校验冲突，冲突则确认失败并提示管理员
- 老师拒绝/超时未确认：管理员在待办中看到，可改派他人
- 导出失败：云函数返回错误信息，前端提示重试
- 表单校验：前端即时校验 + 云函数二次校验

## 8. 测试策略

- 云函数单元测试：排课筛选逻辑（时间覆盖、冲突判定、系列课校验）为重点
- 关键流程端到端手动测试：导入老师 → 录时间 → 排体验课 → 老师确认 → 排正式课系列 → 审批流 → 导出
- 手机端实测：微信内置浏览器 + 系统浏览器

## 9. 分阶段交付

- **一期（核心可用）**：账号体系、校区管理、老师时间/校区录入、体验课+正式课排课、冲突校验、老师确认、课表查看
- **二期（完善）**：时间修改审批流、调课换老师、Excel 导出、站内消息
- **三期（可选）**：微信服务号通知、数据统计报表

## 10. 验收标准（一期）

1. 管理员可批量导入 300 名老师，老师可登录并录入时间与校区
2. 管理员发起体验课排课，候选列表只显示校区匹配、时间覆盖、无冲突的老师
3. 老师确认后课程出现在双方课表中；拒绝后管理员可重选
4. 正式课按总次数生成系列课程，时间冲突的系列无法创建
5. 手机端与电脑端均可正常操作
