# 排课工具一期实施计划

日期：2026-10-26
依据设计文档：`docs/superpowers/specs/2026-10-26-排课工具-design.md`
一期范围：账号体系、校区管理、老师时间/校区录入、体验课+正式课排课、冲突校验、老师确认、课表查看

## 0. 技术选型

- 前端：Vue3 + Vite + Vant 4（移动端组件库，媒体查询适配桌面）；Pinia 状态管理；Vue Router
- 后端：腾讯云开发 CloudBase —— 云函数（Node.js 18）+ 云数据库 + 静态网站托管 + 自定义登录
- 测试：Vitest 单元测试（重点覆盖排课筛选云函数）；关键流程手动测试
- 工具：@cloudbase/cli 部署；腾讯云控制台开通环境（用户需注册腾讯云账号并开通 CloudBase，按量付费）

### 项目结构

```
排课/
├── frontend/                  # Vue3 前端
│   └── src/
│       ├── views/teacher/     # 老师端页面
│       ├── views/admin/       # 管理端页面
│       ├── api/               # 云函数调用封装
│       └── stores/
├── cloudfunctions/            # 云函数（每个一个目录）
│   ├── auth/                  # 登录、注册、批量导入、改密码
│   ├── baseData/              # 校区、学生 CRUD
│   ├── availability/          # 老师时间与可带校区
│   ├── schedule/              # 排课筛选（核心）
│   └── course/                # 排课发起、确认、课表查询
└── docs/
```

## 1. 任务拆解

### 阶段A：基础设施（任务1-3）

**任务1：前端脚手架**
- Vite 创建 Vue3 项目，装 Vant/Pinia/Router，配置移动端 rem 适配与桌面端最大宽度布局
- 验收：`npm run dev` 打开空白首页，手机模拟器与桌面宽度均正常

**任务2：CloudBase 环境接入**
- 用户在腾讯云开通 CloudBase 环境（需用户操作，提供截图指引）
- 前端接入 tcb-js-sdk，封装 `callFunction(name, data)`
- 验收：前端成功调用一个 hello 云函数并返回结果

**任务3：部署管线**
- 配置 cloudbaserc.json：`npm run build` → 静态托管；云函数一键上传
- 写 npm scripts：`deploy:web`、`deploy:functions`
- 验收：线上 URL 可访问 hello 页面

### 阶段B：账号与基础数据（任务4-7）

**任务4：数据库集合与安全规则**
- 创建 9 个集合（users/teachers/campuses/availabilities/students/courses/sessions/approvals/messages）
- 安全规则：默认仅云函数可写（所有写操作走云函数）
- 验收：控制台可见集合，前端直连写入被拒绝

**任务5：auth 云函数**
- login（手机号+密码，签发自定义登录 ticket）、register（老师注册→待审批）、importTeachers（批量导入，生成初始密码）、changePassword、approveTeacher
- 单测：密码哈希校验、导入去重（同手机号）、审批状态流转
- 验收：单测通过

**任务6：前端登录与账号页**
- 登录页、首次登录强制改密码、路由守卫（按角色分流老师端/管理端）
- 管理端：老师管理页（批量导入Excel/CSV、注册审批列表）
- 验收：手动测试——导入3名老师→老师登录→强制改密码→进入老师端；注册1名→管理员审批→可登录

**任务7：校区与学生管理**
- baseData 云函数：校区 CRUD、学生 CRUD
- 管理端页面：校区列表（预置16个校区导入入口）、学生列表（增删改查：姓名/校区/电话）
- 验收：手动测试 CRUD 全流程

### 阶段C：老师端录入（任务8-9）

**任务8：availability 云函数**
- 保存可带校区（多选）、规律时间（星期+时段，可多条）、临时时间（日期+时段，可多条）
- 一期直接生效（审批流属二期），但数据模型预留 approvalStatus 字段
- 单测：时段合法性（结束>开始、不与同类型既有时段重叠）
- 验收：单测通过

**任务9：老师端录入页面**
- 我的校区（16校区多选卡片）
- 我的时间：Tab 切换"每周规律"/"临时日期"，时间段选择器（Vant Picker），列表增删
- 验收：手机端手动测试录入并回显

### 阶段D：排课核心（任务10-13）★ 本项目关键

**任务10：schedule 筛选云函数**
- 输入：{campusId, 日期或星期, startTime, duration, type, totalSessions?}
- 逻辑：校区匹配 → 时间覆盖（规律+临时）→ 冲突排除（sessions 时间交集，正式课校验每次课）
- 单测用例≥12个：边界含跨天时段、整点边界、系列课第N次冲突、待确认状态也算冲突
- 验收：单测全通过

**任务11：course 云函数**
- createTrial（体验课）、createRegular（生成 series sessions）、confirm（老师确认，**确认时二次校验冲突**，冲突则失败）、reject、课表查询（按老师/校区/日期范围）
- 单测：并发确认二次校验、系列课生成数量正确
- 验收：单测通过

**任务12：管理端排课页**
- 两步向导：① 选类型+学生+校区+时间（正式课加时长1h/1.5h/2h+总次数）② 候选老师列表（头像/姓名/可带校区）→ 确认发出
- 验收：手动测试——构造3种老师（校区不符/时间不够/有冲突），验证只有合格老师出现

**任务13：老师端待办与确认**
- 待确认列表（课程信息+校区+时间）、确认/拒绝按钮
- 验收：手动测试确认后双方课表可见；拒绝后管理端待办显示退回

### 阶段E：课表与仪表盘（任务14-15）

**任务14：课表页**
- 老师端：周视图（Vant Calendar 或自绘7天列）
- 管理端：天/周切换，校区+老师双筛选
- 验收：手动测试不同筛选组合

**任务15：管理端仪表盘**
- 今日课程数、待确认数、待审批数（二期审批入口先占位）
- 验收：数字与实际数据一致

### 阶段F：联调上线（任务16-17）

**任务16：端到端验收测试**
- 按设计文档第10节5条验收标准逐条手动执行并记录
- 手机实测：微信内置浏览器 + Safari/Chrome

**任务17：正式上线**
- 部署正式环境、创建2个管理员账号、批量导入300老师（用户提供Excel）
- 交付使用说明（一页图文：老师如何录入、管理员如何排课）

## 2. 风险与对策

| 风险 | 对策 |
|---|---|
| CloudBase 需用户注册腾讯云并实名认证 | 任务2 前置，提供操作指引；不通过则回退方案A（轻量服务器） |
| 排课筛选性能（300老师×每天300课） | 查询用索引（teacherId+日期）；单测覆盖性能边界，必要时加缓存 |
| 微信内置浏览器兼容性 | 任务16 实测；避免使用不兼容 API |
| 用户无技术背景，部署环节受阻 | 任务3/17 由我方操作，用户仅需提供腾讯云账号 |

## 3. 执行顺序与依赖

A(1→2→3) → B(4→5→6→7) → C(8→9) → D(10→11→12→13) → E(14→15) → F(16→17)
- 任务2 需要用户配合（开通腾讯云），其余均可由开发侧完成
- D 阶段单测不通过不得进入 E
